# 睡眠管理Next（Sleep-Manager-Next）

让 Bot 在合适时间、并且自己确认要睡后进入临时睡眠状态，避免 Bot 半夜继续被拉起来聊天、消耗 token。

## 兼容性

| 项目 | 要求 |
| --- | --- |
| 主程序 | `>= 1.2.5`，`<= 1.3.99` |
| 插件 SDK | `>= 2.6.0`，`<= 2.99.99` |
| 第三方依赖 | 无 |
| 声明能力 | `send.text` / `llm.generate` / `config.get` |

## 安装

在插件市场直接安装；或手动安装：

```bash
cd <你的 MaiBot 目录>/plugins
git clone https://github.com/ValleyWinds/Sleep-Manager-Next.git
```

后续更新在插件目录内 `git pull` 后，在 WebUI「插件管理」重新加载即可，无需重启主程序。`config.toml` 存放在插件目录内。

## 睡眠期间会发生什么

进入睡眠后，插件暂停以下链路：

- 新入站消息进入主处理链路
- 表达学习提取和写入
- Planner 响应结果和工具调用
- 睡眠后的后续出站消息

Bot 自己发出"我睡了""该睡了""大家晚安"等短句时，插件会判断是否进入睡眠；用户在允许入睡时间内催睡时，插件只记录一次待确认状态交给 Planner，只有 Bot 随后自己发出明确入睡确认，才会真正睡眠。普通聊天不会每条都调用额外模型。

## 入睡判定

插件默认使用一层轻量 AI 判定器判断 Bot 是否真的在表达"自己要睡"。判定器只接受 `SLEEP / NOT_SLEEP / UNSURE`，只有 `SLEEP` 会触发入睡。

AI 判定只会在允许入睡时间内触发：

- 有待确认催睡时，判断 Bot 随后的回复
- 没有待确认催睡时，只判断 Bot 自己发出的睡眠相关短句，相关关键词可以在"AI 判定触发关键词"里用逗号分隔调整

如果希望完全交给 AI 语义判断，可以开启"AI 判定全部短句"。开启后，允许入睡时间内的所有短出站文本都会进入 AI 判定，不再要求先命中睡眠相关关键词，但模型调用次数会增加。

为了避免被诱导睡觉，插件默认只接受短句、自我入睡或群体收尾晚安。带 `@`、明显称呼别人、引用回复、或"晚安，某某"这类对个人说晚安的内容不会触发。正则规则仍保留为 AI 不可用或结果不确定时的兜底。

AI 判定模板内置在插件代码中，不依赖主程序 Prompt 目录。

## 睡眠状态与唤醒

睡眠状态保存到 `data/plugins/<插件 ID>/sleep_state.json`。重启后会恢复尚未过期的睡眠状态；预计醒来时间已过则自动清理。

- **自然到点醒来**（默认开启）：进入睡眠后才启动后台检查任务，不调用 LLM、不消耗 token。关闭后改为懒唤醒（有人发消息或查询时才唤醒）
- **手动唤醒**：`/sleep wake` 与 `/sleep wake_all` 命令，见下文

睡眠状态默认按作用域隔离：配置了单独作息的群、未配置单独作息的群和私聊各自独立；想让默认聊天流共用全局睡眠状态，可以关闭"默认聊天流独立睡眠"。

## 静默入睡

"静默入睡"默认关闭。开启后在后台检查两个计时器：

- `完全安静入睡时间（分钟）`：没有任何入站或出站消息多久后入睡
- `无参与入睡时间（分钟）`：Bot 连续多久没有参与话题后入睡

静默入睡不调用 LLM，也不会额外发送"晚安"。无参与计时只会被 Bot 出站消息或有效 Planner 动作刷新，`no_action`、`no_reply`、`no_react` 等空动作不算参与。

## 分群作息

全局"作息"是默认时间配置（允许入睡起止、目标醒来时间、最短/最长睡眠分钟、醒来随机浮动）。需要某个群单独使用不同作息时，在"分群作息"里按群号添加覆盖配置，命中群号时分群配置优先。

## 睡醒回顾

"睡醒回顾"默认关闭。开启后，插件会在睡眠期间保存被拦截消息，并在对应作用域醒来时生成本地回顾文件（路径：`data/plugins/<插件 ID>/sleep_review/reports/`），内容包括群号、群名、私聊用户、睡眠期间的轻量聊天记录和每个聊天流的简短总结。

插件不会向群聊或私聊补发历史回复。

> **注意**：回顾文件包含完整的用户 ID、消息原文等**敏感数据**，长期保存在插件数据目录。备份或分享数据时请注意脱敏；不需要时建议定期清理 `sleep_review/` 目录。

## 命令

- `/sleep help`：查看命令帮助
- `/sleep status`：查看当前聊天流对应作用域的睡眠状态
- `/sleep wake`：手动唤醒当前聊天流对应作用域，不解除全部聊天流睡眠
- `/sleep wake_all`：手动唤醒全部聊天流，解除所有睡眠作用域
- `/sleep now`：在当前作息允许入睡时记录一次管理员催睡，等待 Bot 自己确认
- `/sleep forced`：无视时间窗口，让当前作用域立即睡眠
- `/sleep forced_all`：无视时间窗口，让全部聊天流进入睡眠

`/sleep now`、`/sleep forced` 和 `/sleep forced_all` 是管理命令，可以通过"允许管理入睡命令"关闭。"管理员用户 ID"留空时管理命令对所有人不可用（默认安全），需填写至少一个用户 ID 才能启用。

> **注意**：如果同时关闭"允许控制命令"和"自然到点醒来"，睡眠期间所有 `/sleep` 命令都会失效，只能等睡眠自然到期。建议至少保留其中一项，避免 Bot 长时间静默无法干预。

## 日志

插件默认把运行日志滚动写入 `data/plugins/<插件 ID>/logs/sleep_manager.log`，排查行为问题时直接看这个文件。日志有体积上限（单文件 512KB、最多 3 个备份，约 2MB），不会无限增长；级别和开关可在 WebUI"日志"节调整，日常排查用 `INFO`，需要更细链路时再开 `DEBUG`。
